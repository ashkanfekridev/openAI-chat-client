رابط کاربری و امنیت

تقسیم مسئولیت Blade، Livewire و JavaScript و کنترل‌های امنیتی دسترسی و نمایش محتوا.

Blade

resources/views/chat.blade.php shell اصلی، فرم چت، dialog تنظیمات، template پیام‌ها و URL endpointها را با attributeهای data-* در اختیار JavaScript می‌گذارد. viewهای جدا برای auth، پنل مدیر، اشتراک عمومی و چاپ وجود دارند.

Livewire Sidebar

کامپوننت class-based ConversationSidebar فقط روی داده‌های کاربر فعلی کار می‌کند و این رفتارها را دارد:

  • جستجوی live در عنوان و محتوای پیام با debounce سیصد میلی‌ثانیه
  • فیلتر پوشه و آرشیو در query string
  • مرتب‌سازی گفتگوهای pinشده و سپس آخرین تغییر
  • ساخت، تغییر نام و حذف پوشه با validation و Policy

JavaScript مرورگر

چرخه چت

fetch، AbortController، رندر تدریجی، history و notification.

محتوا

فایل، تصویر، Markdown، copy، resend و خواندن صوتی.

تنظیمات

مدل، system prompt، reasoning، temperature، وب و دانش.

ترجیحات

ذخیره theme و مدل انتخابی در localStorage.

رندر امن Markdown

پیام کاربر همیشه متن ساده است. برای پاسخ دستیار، parser داخلی با ساخت مستقیم nodeهای DOM از تیتر، فهرست، نقل‌قول، جدول، لینک و code block پشتیبانی می‌کند. HTML خام مدل به DOM تزریق نمی‌شود و لینک فقط با protocolهای زیر فعال است:

http:  https:  mailto:

احراز هویت

  • User قرارداد MustVerifyEmail را پیاده‌سازی می‌کند.
  • چت نیازمند login، حساب فعال و ایمیل تأییدشده است.
  • password با cast نوع hashed ذخیره می‌شود.
  • session پس از login/register regenerate و هنگام logout invalidate می‌شود.
  • ورود و ثبت‌نام با throttle پنج درخواست در دقیقه محافظت می‌شوند.

Authorization و فایل خصوصی

سطحکنترل
Routemiddlewareهای guest، auth، active، verified و admin
ورودیForm Request برای validation و authorization
ResourcePolicy یا شرط مالکیت user_id
پیوستمالکیت گفتگو، تعلق پیام، prefix مسیر و وجود فایل
عمومیshare token یکتا به همراه shared_at

دسترسی غیرمجاز به منابع متعلق به کاربر دیگر معمولاً 404 می‌دهد تا وجود resource افشا نشود. فایل‌ها public نیستند و تنها از controller کنترل‌شده قابل دریافت‌اند. پاسخ دانلود نیز header X-Content-Type-Options: nosniff دارد.

سهمیه و مدیریت

قبل از درخواست OpenAI، دوره مصرف refresh و سقف بررسی می‌شود. مدیر می‌تواند نقش، وضعیت، مدل‌های مجاز، سقف و دوره روزانه/ماهانه را تغییر دهد. غیرفعال‌سازی حساب خود مدیر از پنل جلوگیری می‌شود.
