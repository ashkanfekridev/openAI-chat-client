جدول conversations

  • id از نوع UUID است.
  • openai_response_id زنجیره context را برای درخواست بعدی نگه می‌دارد.
  • system_prompt، reasoning_effort، temperature، web_search و use_knowledge برای هر گفتگو مستقل‌اند.
  • folder_id اختیاری است؛ pin و archive برای مرتب‌سازی sidebar استفاده می‌شوند.
  • share_token یکتا است و همراه shared_at دسترسی عمومی را فعال می‌کند.

پیام و پیوست

هر پاسخ موفق دو رکورد پیام ایجاد می‌کند: یکی با role کاربر و یکی با role دستیار. مصرف توکن، شناسه پاسخ OpenAI، citation و هزینه تقریبی روی پیام دستیار ذخیره می‌شوند.

آرایه JSON پیوست شامل نام، MIME، نوع و مسیر خصوصی است. متد ChatMessage::toChatArray() کلید path را حذف و URL endpoint کنترل‌شده دانلود را جایگزین می‌کند. فایل‌ها در مسیر زیر قرار می‌گیرند:

storage/app/private/chat-attachments/{conversation-uuid}/{generated-name}

قواعد حذف و یکپارچگی

  • حذف کاربر، رکورد گفتگوها، پوشه‌ها و اسناد وابسته را در دیتابیس cascade می‌کند.
  • حذف پوشه فقط folder_id گفتگو را null می‌کند.
  • حذف گفتگو، پیام‌های دیتابیس و پوشه فایل آن گفتگو را حذف می‌کند.
  • حذف سند از endpoint برنامه، فایل OpenAI و فایل local را نیز پاک می‌کند.
  • Vector Store کاربر پس از حذف آخرین سند به‌صورت خودکار حذف نمی‌شود.
حذف مستقیم رکوردها در دیتابیس cleanup منابع storage یا OpenAI را تضمین نمی‌کند؛ عملیات حذف باید از endpointهای برنامه انجام شود.

مصرف و هزینه

جدول کاربران شمارنده‌های input، output و total دوره جاری را نگه می‌دارد. مقدار token_limit=null به معنی مصرف نامحدود است. هزینه تقریبی هر پیام در estimated_cost_micros و بر اساس قیمت مدل در config/services.php محاسبه می‌شود.
